## 1. 有更好办法的阶段
- **第 7 阶段：开算前先锁"构型和电子态的选取规则"。** 只写判读标准还不够，还要预先写明：几个自旋初值、取最低还是取指定分支、低能分支是否纳入。规则一旦锁定，后面不再改。
  - 实例：11-19 定的"取已算构型中最低"和 11-20 13:36 定的"低能分支不考虑"互相冲突。T039 的"颗粒推后过氧化 0.48 V"正好卡在这个冲突上，花了一整天才判定写不进正文。
- **第 3、4 阶段：每个新 idea 或新实验，先做零成本检验。** 先用已有数据或文献判一次，判不了才设计新实验或新计算。
  - 实例：用 XANES、SEIRAS 现有数据核"Mn=O 取哪个分支"，一小时内就得出"判不了"。原位 XANES 本来就做不了，这一点设计时就该知道（见第 3 节的约束清单）。
- **核查分级，不要所有内容都多路审。**
  - A 级（摘要、标题、机理主张、进 FACTS 的数字）：跨家族两路。
  - B 级（正文常规段、图注）：一路。
  - C 级（讨论文件、想法）：不核。
  - 实例：摘要从 11-20 晚到 11-21 下午，六方出了十几版、五份"综合版"，有一小时内出了五份综合，大部分 token 花在综合别人的综合上。
- **合并只由一个指定方来做。** 其他方只交意见，不交"综合版"。这条 ROLES.md 对写作已经这样定了，建议推广到所有阶段。
- **数字带出处标签，用脚本检查。** 草稿里每个数字后跟 `[F:编号]`，指向 FACTS.md；脚本列出所有没带标签的数字。
  - 实例：参比电极我误记成 Ag/AgCl；1.011 V 和 1.016 V 两种口径并存；还有 Antigravity 的错 DOI。这些错都出在"凭记忆引数"上。

## 2. 动手池（含我）最能发挥作用的地方
- **"反例扫描"作为固定步骤，放在第 10 阶段冻结主线之前。** 拿主线里的每个主张，用仓库里所有已有输出去找反例，只读复算，不做新计算。这是 Claude Code cloud 最适合的活。
  - 实例：用已有数据扫出三处问题：
    - 同一个轴向 OH 放到无颗粒的 Mn–NC 上，极限电位只有 0.57 V，"OH 本身就让吸附适中"不成立；
    - 工作态"Mn 带 OH"依赖电子态分支的选择；
    - dz² 机理句和 T041 的拆分结果矛盾。
  - 这三处都是在写摘要时才发现的，如果在冻结主线前扫一遍，就能提前发现。
- **动手池给思考池写简报，省思考池的 token。** 思考池不直接读仓库，只读动手池写的简报：一页以内，每个数字带出处。
  - 实例：Antigravity 给 Gemini 写的简报，Gemini 据此出的三版质量不错。
- **动手池之间的复核要跨家族。** Claude Code 本地和我是同一家族，互核只能算半份。数字互核至少要有一方是 Codex 或 Antigravity。

## 3. 缺的环节
- **约束清单 `CONSTRAINTS.md`**：做不了的事、要等的事、额度。项目开始就写，设计阶段先查它。
  - 实例：原位 XANES 做不了；没有 Mn–NC 的 XAS 和 SEIRAS；没有 BET 数据。
- **问题预算与停车场。** 新问题必须写明"会改变哪个决定或哪句话"，写不出就放进 IDEAS_BOARD 的待议区，不开新计算。
  - 实例：赵月 11-20 说过"而不是一直在提出新的问题，然后不断做新的计算来回答新的问题"。
- **模型与真实材料对应的检查**，放在第 7 阶段：模型的几何、可及性、状态（干态还是工况）和真实材料是否对得上。
  - 实例：CW2-19 讨论过"两面可接触电解液"，是写摘要时才问出来的。
- **查新前移到第 3 阶段。**
  - 实例：Wan et al. 2022（Nat. Commun.）已报道团簇诱导轴向 OH，到 11-20 写摘要时才被提出来。
- **额度看板**：在 STATUS.md 里给各方加"额度：充足/将尽/用完，恢复时间"一列，派活时先看这一列。
