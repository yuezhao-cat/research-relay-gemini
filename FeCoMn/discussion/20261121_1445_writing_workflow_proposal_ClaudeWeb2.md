依据：20 日到 21 日写机理和摘要的实际经过。README 的角色表保留，本文件只补“怎么推进”。是否写进 README 由赵月决定。

1. 先写后定机理。摘要和图 6 段写了很多轮，主线中途从“适中”变成“推后过氧化”，又因分支问题退回，大部分返工来自机理没定就开写。

3. 赵月的决定分散。决定写在各方回复记录里，智能体常常不知道已经定过，重复提已否定的方案。
4. 赵月当传话筒。大量时间花在转发和解释上。
5. 轮次不设上限，每方都在改每一处。

## 二、写作顺序（每篇论文都按这个顺序，前一步不定，后一步不开写）
1. 主线与证据链：每一环写明证据、证据类型、还缺什么（参照 discussion/20261120_1905_borrowed_evidence_chain）。赵月定稿后冻结。
2. 数据事实表：进入正文的每一个数字，写明数值、单位、来源文件、计算口径，并由另一方从原始文件复核，标“已复核”。只有表里的数才能进稿。
3. 图和 SI 表：按主线定面板，数字只取自事实表。
4. 正文结果与讨论段落，按图的顺序写。
5. 引言最后一段、结论。
6. 摘要和标题最后写，只概括已经写定的内容。
7. 投稿前一致性终检：数字、图表编号、术语、引用。

## 三、每个写作单元的固定流程（一个段落、一张图、摘要都算一个单元）
1. 赵月开单元：在 discussion/ 建一个文件，写清目标、已定事项、不许写的内容、截止轮次。各方只回应这个文件。
2. 起草：一方起草（英文写作 Gemini 或 Claude 为主），每句标数据来源。
3. 并行审阅，固定分工：
   - Claude Code 或 Codex：每个数字与事实表、原始文件是否一致。
   - Claude web：实验证据的表述是否越界。
   - GPT：因果是否超出证据。
   - Antigravity：格式与写作规则（冒号分号、含糊词、防御性写作、词数、术语统一）。
   审阅只写问题、依据和建议改法，不各自另起一稿。
4. 综合：指定一方做逐项取舍表（问题、各方意见、采用、理由），给出一个版本。
5. 赵月拍板，只看取舍表和最终稿。
6. 轮次上限：每个单元最多两轮审阅。两轮后仍有分歧，列出分歧由赵月直接定。

## 四、三个公共文件
1. DECISIONS.md（每个项目一个，只有赵月的决定）：日期、决定、理由、影响范围。各方每次开工前先读，违反已定事项的意见直接作废。今天分散的决定（不考虑低能分支、工作态为 Mn–OH、只用现有数据、摘要不放机理对比、热解碳多孔等）先汇总进去。
2. FACTS.md（每个项目一个）：已复核的数据事实表，含来源和复核人。
3. IDEAS_BOARD.md：保留，用于新想法，各方用前缀编号（已在用），被否定的标“已否定”。
